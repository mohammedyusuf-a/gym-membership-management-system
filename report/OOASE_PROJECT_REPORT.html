1. Introduction

1.1 Overview

Fitness Athlete Club (operating as Titan Iron Gym) is an advanced, high-performance web-based athletic club and gymnasium management system specifically engineered for Olympic powerlifting facilities, strength academies, and commercial gymnasiums in Salem, Tamil Nadu. The system centralizes member registration, athletic progress tracking, fast touchless QR/barcode attendance scanning, personal coach assignments, Indian Rupee (INR ₹) tier billing, and a real-time e-commerce supplement store.

The software guarantees robust role-based security by strictly separating normal customer/member portals from the restricted Creator & Master Admin portal. While public users log in to their personalized Member Profile to upload profile pictures (DP), update body metrics (height, weight, body fat percentage), and accept club safety liability waivers, the website creator exercises full administrative control over member rosters, coach assignments, financial revenue reports, and facility operations through a discreet master key portal.

The project was designed, modeled, and developed following strict Object-Oriented Analysis and Software Engineering (OOASE) principles: requirements specifications, comprehensive UML modeling (Use Case, Class, Sequence, Activity, State Chart, Component, and Deployment diagrams), client-side single-page architecture (SPA) in modern JavaScript (ES6+), persistent browser LocalStorage data modeling, responsive Vanilla CSS3 dark-mode aesthetics, and production deployment on Vercel's global edge network.

1.2 Problem Statement

Conventional athletic clubs and private gyms often rely on manual paper logbooks, isolated spreadsheets, and unmonitored counter transactions, leading to critical operational bottlenecks:

  • Unrestricted Entry & Expired Memberships: Lack of real-time check-in validation allows expired or unauthorized members onto the training floor.
  • Scattered Athlete Data: Personal contact info, health waivers, height/weight logs, and training goals are kept across loose paper forms.
  • Exposed Administrative Controls: Traditional gym sites display master admin login inputs on the public login page, risking credential theft by regular visitors.
  • Absence of Digital Identity: Members lack digital photo identification and touchless check-in passes.
  • Disconnected Nutrition Sales: Protein powders and gym supplements are sold manually without inventory tracking, shopping cart calculation, or instant UPI payment verification.
  • Lack of Real-Time Reporting: Attendance rates, expiring memberships, and daily collection figures require hours of manual calculation.

1.3 Objectives

  • Centralize athletic member directories, certified coaches, membership tiers, and pro shop products in an integrated web platform.
  • Provide a dedicated Customer Profile & Fitness Dashboard where athletes can upload profile pictures (DP) that stay permanently saved, log fitness body metrics, track workout streaks, and agree to club health waivers.
  • Implement a Restricted Creator Admin Master Key accessed solely via discreet golden key triggers, completely shielded from standard member login pages.
  • Enable real-time Touchless Barcode / QR Code Check-in with instantaneous access grant or expiry denial.
  • Deliver an authentic Pro Supplement Shop with real-time cart drawer, coupon application, and Google Pay (GPay) / PhonePe UPI payment simulation.
  • Model the complete system architecture using standard object-oriented UML diagrams.
  • Deploy the production application globally with automated CI/CD on Vercel: https://fitness-athlete-club.vercel.app/.

1.4 Scope of the Project

  • Included: Member registration and authentication, customer profile dashboard, permanent DP photo upload, fitness body metrics tracking, club safety and medical waiver acceptance, member directory with search and status filters, printable digital ID passes, 1-click renewal with automated invoice generation, certified trainer profiles (featuring leading Tamil fitness athletes such as Surabi, Dolphin, Biglee Murali, Saran Fitness, and Kabilan), pro shop with real-time cart, UPI QR code generation, CSV data export, and dark-mode athletic user interface.
  • Not included: Native mobile app stores (built as a mobile-first progressive web responsive app), hardware biometric turnstiles, and bank credit card merchant accounts requiring physical POS swipe hardware.

2. Requirement Analysis

2.1 Approach

Requirements were gathered by analyzing real-world gymnasium workflows at Olympic athletic facilities in Tamil Nadu. The object-oriented approach was adopted: primary system actors were identified, their functional goals decomposed into discrete use cases, domain entities mapped to class hierarchies, and operational constraints translated into enforceable business rules.

2.7 Business Rules

  • Creator Isolation Rule: Administrative master credentials must never be rendered or pre-filled on the general public login card. Creator login is initiated exclusively via dedicated golden key triggers.
  • Permanent DP Persistence Rule: A member's uploaded profile photo must persist across browser reloads, logouts, and tab restarts, remaining active until the member explicitly uploads a new photo or clicks remove.
  • Check-in Expiry Lock Rule: A member with an Expired status is immediately blocked at the entry terminal with an Access Denied alert and prompted to renew.
  • Waiver Mandate Rule: Members must accept the Club Terms, Safety Rules, and Health Liability Waiver before floor access is granted.
  • Real-Time Cart Calculation Rule: Total payable amounts must dynamically recalculate when quantity, flavor, size, or coupon discounts are applied.

Sequence diagram description: Traces the end-to-end execution when an athlete uploads a profile photo. Figure 3.4: Activity Diagram – Member Onboarding & Administrative Workflow
Activity diagram description: Illustrates parallel activity branching. Depending on whether the actor activates the Creator Master Key or authenticates as a standard Gym Member, the system routes the user either into the administrative control deck (roster exports, revenue audits) or directly into the athletic Customer Profile (permanent DP upload, metric logging, waiver acceptance, and QR badge presentation).
Figure 3.5: State Chart Diagram – Member Lifecycle & Entry Terminal Verification
State chart diagram description: Models state transitions across the membership lifecycle. An athlete begins in the Active state, shifts to Expiring Soon when remaining duration is under 7 days, and enters Expired when validity ends. When an ID barcode is scanned at the terminal, active subscriptions trigger the Access Granted state; expired accounts trigger Access Denied, opening an instant renewal pathway.
Figure 3.6: Component Diagram – Software Architecture
Component diagram description: Deconstructs the system into loosely coupled modules: the Single-Page Presentation UI, the Application Controller / Router, the persistent GymStore Data Engine, and the dynamic UPI QR generator. Components communicate via clean JavaScript APIs and standard DOM events.
Figure 3.7: Deployment Diagram – Physical Architecture & Vercel Edge Hosting
Deployment diagram description: Details physical network topology. The client browser (running on desktop workstations or mobile devices) downloads encrypted production bundles from Vercel's global CDN over secure HTTPS (Port 443). Member state, permanent DP images, and daily logs are executed and maintained with zero latency directly within the browser's persistent LocalStorage engine.

4. Project Coding

4.1 Architecture Overview

Fitness Athlete Club is architected as a decoupled, high-performance Single-Page Application (SPA). The presentation tier utilizes semantic HTML5 markup styled with a modular, high-contrast Dark Athletic design system (`css/styles.css`). The application logic tier (`js/app.js`) handles event delegation, modal dialog lifecycles, view routing, real-time cart manipulation, and FileReader image encoding. The data tier (`js/data.js`) encapsulates the GymStore engine, responsible for seed initialization, persistent localStorage synchronization, and query execution.

6. Conclusion and References

6.1 Conclusion

The Fitness Athlete Club (Titan Iron Gym) project successfully demonstrates how Object-Oriented Analysis and Software Engineering (OOASE) methodologies can be applied to build a modern, high-performance club management and athletic training web platform. The requirement analysis delineated clear actor responsibilities, resulting in strict architectural separation between public member portals and restricted creator administration.

The complete software development lifecycle was executed rigorously: from requirements specification and structural UML modeling to modular client-side single-page implementation and automated production deployment on Vercel. Critical features—including permanent profile picture (DP) storage, touchless QR attendance checking, Indian Rupee billing, and real-time UPI supplement e-commerce—were thoroughly tested and verified. The platform provides a seamless, professional experience for athletes, coaches, and administrators alike.

6.2 Limitations

  • Client-Side Storage Boundary: Browser LocalStorage stores data within the client domain; cross-device synchronization requires cloud database replication.
  • Payment Processing: UPI transactions are simulated for real-time order generation; live production bank gateway webhooks are not yet connected.
  • Hardware Turnstile Integration: Barcode and QR check-in operates via digital screen simulation without direct interface to physical electronic magnetic door latches.

6.3 Future Enhancements

  • Backend Cloud Synchronization: Migration of LocalStorage schema to a cloud database (MongoDB / PostgreSQL) with JWT token authentication.
  • Native Mobile Application: Packaging as a Progressive Web App (PWA) with push notifications for workout reminders.
  • Hardware Access Control: Integration with physical RFID wristbands and automated turnstile barrier relays.
  • Personalized Workout Tracking: Set-by-set exercise logging and 1-Rep Max (1RM) strength progression graphs.
